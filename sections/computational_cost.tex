\subsection{Computational Cost}
\label{app:computational_cost}

\paragraph{Measurement setup.}
We profile GPU field prediction on the first, middle, and last test cases
of each benchmark, using sampling seeds 0, 1, and 2. Each case runs on one
NVIDIA H20 GPU with FP32 networks and batch size one. After warm-up, we time 20
repetitions per sampled-field request (five for DrivAerML) and five per
request that reconstructs a full field from fewer points, with CUDA
synchronization around each measurement.
The tables report the mean and sample standard deviation of the nine
case--seed mean latencies. Full mesh uses the same frozen backbone at
$100\%$ of the reference points and is averaged over the three cases.

\paragraph{Sampling overhead.}
Table~\ref{tab:inference_time_sampled} includes coarse inference or the
learned head, density construction, point selection, compensation, final
inference, decoding, and transfer of sampled predictions to the CPU.
Across the 24 task--budget pairs, PI costs $1.015$--$1.048\times$ the
Uniform latency, and CA costs $1.013$--$1.557\times$.
CPG executes both the complete coarse and final operators, giving
$1.157$--$2.152\times$ the Uniform latency. CA is faster than CPG at every
measured budget. At a $37.5\%$ budget, its sampled-field request is faster
than full-mesh inference on seven of the eight tasks.

\paragraph{Execution and preparation.}
The profiles measure repeated requests after model loading and
geometry-dependent preparation. Uniform and PI reuse point sets determined
by the input, geometry, seed, and budget. CPG and CA recompute their draft
predictions or head outputs, scores, and adaptive point sets on every request.
Reusable work consists of geometry operators, candidate structures, and CUDA
graphs. Changing their input dependencies requires preparation again.
Data loading, initialization, ground-truth error evaluation, and file writing
are outside the reported request times.

The profiling configuration for Elasticity uses a $25\%$ coarse set and a
two-block head. Its accuracy configuration in
Appendix~\ref{app:density_policy_design} uses a $10\%$ coarse set and an MLP.
Pipe and Darcy retain their two-block heads in these profiles.
GPU sampling also uses implementation-specific FPS placement and seeded
sampling realizations. The field errors below are measured on the same
profiling cases with these implementations.

\paragraph{Full-field reconstruction.}
Table~\ref{tab:inference_time_reconstruction} adds reconstruction and
transfer of the complete reference field at a $50\%$ point budget.
For Pipe, Darcy, Plasticity, Airfoil, and SuperWing, the GPU variant uses
local weighted linear fits over eight neighbors. Elasticity retains
Delaunay interpolation. ShapeNet-Car and DrivAerML retain four-neighbor
inverse-distance interpolation and nearest-neighbor reconstruction,
respectively. Fixed interpolation maps can be prepared for Uniform and PI,
whereas adaptive point sets require updated maps on each request.

Reconstruction can dominate the online cost. For CA on SuperWing,
the sampled-field request takes $8.49$~ms, while the original full-field
path takes $195.87$~ms. GPU local reconstruction reduces the latter to
$10.65$~ms, with the measured field error changing from $2.685\%$ to
$2.749\%$. Elasticity retains its reconstruction cost: its full-field CA
request takes $5.34$~ms, compared with $1.26$~ms for full mesh. Thus, the
benefit of a smaller point budget depends on both the requested output
and the reconstruction operator.
