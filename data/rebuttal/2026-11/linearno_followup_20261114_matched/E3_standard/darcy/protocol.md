# Darcy matched-cohort protocol

Use the shared split_seed20261114:900 training cases and100 validation cases from the original1000 smooth1 pool. Smooth2 rows0–199 remain the200 test cases, historically viewed but unused for selection in this cohort. Fit global channel means/stds on the900 training cases only.

Train native Transolver3 (128 width,8 layers,8 heads,MLP2,64 slices) and official point-temp LinearNO (128/8/8,MLP1,key dimension64), with an additional untouched official conv-temp Full-only baseline. The conv variant cannot evaluate arbitrary retained sets; the point variant is a separate official class, not a converted convolution model.

All three receive native85x85 observations (7225 points), batch4, seed0,1000epochs/225000updates, AdamW1e-3 and OneCycle .3 warm fraction. A shared physical relativeL2 plus0.1 derivative penalty follows official Darcy; this differs from the historical T3 normalized-loss runner. Architecture-specific official clipping/weight decay is kept and recorded in protocol_lock.json. Validation physical L2 selects checkpoints; no test feedback.

Main PI uses the pre-test two-dimensional interface-distance correction with frozen amplitude.25, length2/84,beta.5. The historical flattened one-dimensional distance is not silently relabeled. CPG/CA use coarse722,32 patches,kappa2 and grad_lap; paired CPG beta0/1 share exact predictions and indices. Each backbone receives its own two-block CA head trained on its own first-block features and frozen-model coarse score teacher, with900/100 split and1000head epochs.

`coarse_prediction` and its byte hash refer to the normalized backbone solution output, before physical decoding. This preserves the native Darcy `grad_lap` acquisition semantics and the CA teacher's existing normalized-output definition. The retained final prediction is decoded with the locked output standard deviation and mean, reconstructed to the full grid, and only then compared with the physical solution. Coarse and final prediction arrays therefore have different declared spaces.

Runtime loading checks that the backbone normalizer hash equals the actual current `data/normalizer.npz` hash. Loading a CA head additionally requires its normalizer hash to equal both; this is separate from the operator checkpoint and head weight hashes. Missing or mismatched normalizer identities are rejected before head inference.

Final evaluation is locked to accepted reconstruction v1.1: `grid_scipy_linear_nearest_native_v1` versus `grid_qhull_sparse_apply_v1p1`, source SHA `39cb025024ce5e3899fb18b435243c2c0a806ba19a360dd9201e805e5c93fa17`. Geometry-only acceptance is supplemented by each new checkpoint's preselected validation cases and all test predictions. The field tolerance is `1e-6 + 1e-5*abs(old)` and field-metric tolerance is `1e-7 + 1e-5*abs(old_metric)`; no result-driven relaxation. Coordinates remain the stored FP32-origin native xy promoted to FP64.

Each point backbone has 9,200 physical requests: 200 Full plus five variants × three budgets × three seeds × 200 cases. Each request produces old/new metrics from the same retained prediction. The first evaluation phase publishes Full/Uniform/PI/CPG (7,400 requests); the corresponding CA head is then trained and its 1,800 requests appended. The convolution baseline has 200 Full requests only. Final totals are 18,600 physical requests and 37,200 metric rows. Main rAUEC uses matched Uniform per seed, then mean/sample SD across the three sampling seeds; Full is not part of the integral.

For concurrent collection, `records/{model}/metrics_baseline.csv` and `baseline_completion.json` preserve the completed first phase while the live `metrics_records.csv` is extended with CA. The final phase publishes `metrics_complete.csv` and `complete_completion.json`; the convolution model publishes only this final pair. Each completion receipt is published after its immutable CSV and binds its hash, checkpoint, normalizer, methods, population and counts. Repeating publication with identical bytes is allowed; conflicting existing files are rejected without replacement. Global collection reads these phase snapshots rather than the live CSV or mutable running status.

Formal timing uses preselected test cases 1000, 1099 and 1199, retaining 2,709 / 3,612 / 5,419 points at the three budgets. Full has no sampling seed. Timed methods are Full, Uniform, PI, CPG β=1 and CA; CPG β=0 remains an accuracy-only mechanism condition and receives no borrowed timing. The A/B/C matrix contains 333 groups, 1,323 physical timing conditions, 26,460 warmups and 132,300 formal observations. Group order is randomized with seed 20261114; each group interleaves old/new and backbone observations with saved cyclic order. All models use eager FP32 with TF32 disabled.

Scope A is CPU input → complete CPU float64 output and rebuilds reconstruction mappings every request. Scope B is GPU-resident input → complete GPU float64 output, including required CPU scoring, mapping and transfers within each request. Scope C is CPU input → complete CPU float64 output with only the interpolation map cached by physical case, coordinate dtype/values and selected-index order. It recomputes prediction, score and selection on every call. C compares cached CPU sparse application with cached GPU sparse application under separate IDs; it is not native A timing. Uniform receives the same caching opportunity.

The native CPG/CA constructors also build MiniBatchKMeans patches on the full lattice. Those patches are rebuilt inside every CPG/CA request in A, B and C, so the main timing does not silently use constructor-time geometry preparation. A separate geometry probe reports this cost; it is already present in the acquisition and direct request measurements. This does not alter the algorithm, coordinates, patch count or seed.

At the A boundary, inputs are model-ready CPU FP32 xy coordinates and coefficient features normalized with the locked training normalizer. B receives those same arrays already on GPU. Both include physical prediction decoding inside the request. Data-file reads and preparation of these input tensors are separately recorded in `timing/input_preparation.json`; the latency is not a disk-file-to-field measurement. The separate FP64 reconstruction coordinates are promoted from the stored FP32 values exactly as required by the accepted protocol.

Full forwards the original complete input tensors directly. It does not index or gather an `arange(N)` copy; sampled and coarse requests keep their required indexing. Accuracy, profiling, warmup and direct timing share this native Full path, and Full still has no sampling seed.

The directly timed callable has no phase clocks or synchronization barriers inside the request. GPU synchronization occurs at both request boundaries. Each condition has 20 warmups and 100 formal repetitions. Five separate profiling passes measure reconstruction including its required output transfers and individual stages; stage sums do not replace request wall time. Complete outputs are checked against the retained prediction arrays from accuracy evaluation, and retained/coarse indices plus compensation-weight hashes are checked outside timed rounds. Failed stage profiling preserves completed direct timing and can resume independently.

Memory runs in 11 isolated architecture/method processes. They measure cold-request and warmed PyTorch allocator peaks, with post-request NVML device-memory samples. CPU SciPy allocations and transient external GPU peaks are outside the certified scope. C additionally records map bytes, a separate first-map-build profile, actual first request cost and derived first-plus-reuse totals. Setup, kernel warmup, CPU threads/affinity, hardware, library versions and occupancy are recorded separately.

Controllers require 30 seconds of no GPU compute processes before admission and do not terminate external workloads. Darcy T3 waits for GPU0; point-temp LinearNO waits for GPU1; conv-temp waits for GPU5. After all final accuracy matrices are complete, `postprocess_workflow.py` waits for GPU0 and runs all timing conditions on that same physical GPU. No remote push, paper-result replacement or Feishu write is part of this package.
